Layered architecture

Customers only need to understand the first two layers. The platform handles the rest.

1. Customer systemsWebsite, backend service, internal tool, or AI agent.
2. One simple APIOpenAI-compatible request format for easy adoption.
3. Entry controlAPI keys, request limits, usage checks, and logs.
4. Model controlModel registry, route rules, aliases, and future fallback.
5. Provider adapterTranslates gateway requests to provider-specific requests.
6. Model providerQwen today, more providers later.

What is being simulated?

The customer sees one model name. The gateway decides which real provider model should answer. Today the route is simple and local. Later it can include cost, speed, region, customer plan, and fallback rules.
